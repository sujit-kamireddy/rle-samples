# Baked `code_repair` Dataset Snapshot

`train.jsonl.gz` and `validation.jsonl.gz` are generated by
[`../scripts/build_dataset.py`](../scripts/build_dataset.py) from
[`princeton-nlp/SWE-bench_Verified`](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified),
filtered down to the 43 `django/django` version-`3.2` instances (the
largest single-repo, single-environment slice in SWE-bench-Verified), minus
3 instances with a malformed upstream `FAIL_TO_PASS` entry -- 40 rows total,
32 train / 8 validation. See `source.json` for row counts/checksums and the
exact selection.

Each row is `{instance_id, base_commit, problem_statement, test_patch,
fail_to_pass}`. The environment resolves a row to a workspace at `reset()`
time via `git worktree add --detach <path> <base_commit>` against the
`django/django` clone baked into the image at build time (see
`../Dockerfile`) -- no network access is needed at runtime. Grading applies
`test_patch` and runs `fail_to_pass` via Django's own
`tests/runtests.py`.

The snapshot is baked in and checked in here so that building this image
needs no Hugging Face/network access at all, matching `math_rl`/`code_rl`'s
data snapshot approach. Re-run `build_dataset.py` (from the repository
root, e.g. `python -m examples.gym.openenv.code_repair.scripts.build_dataset
--out-dir examples/gym/openenv/code_repair/env_data`), then gzip the
outputs into this folder to refresh the snapshot.
